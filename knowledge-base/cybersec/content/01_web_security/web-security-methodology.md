# Web 与 API 安全测试方法

## 测试前

确认应用、域名、账号、测试类型、禁止操作、速率限制、数据处理规则和联系人。优先使用测试账号与无害数据。

## 分析面

- 输入验证：参数、JSON、Header、Cookie、文件和路径。
- 身份认证：登录、会话、MFA、密码重置和 Token 生命周期。
- 授权：水平越权、垂直越权、对象级授权和租户隔离。
- 服务端请求：URL 解析、重定向、出站访问和网络分段。
- 文件处理：上传类型、存储位置、解析器和下载权限。
- 业务逻辑：状态机、重复提交、金额/权限边界和并发。
- API：版本、错误信息、限流、Schema 校验和敏感字段暴露。

## 证据记录

每个发现至少记录：前置条件、最小复现步骤、请求与响应摘要、受影响组件、影响、修复建议和复测结果。敏感值应脱敏，不要把真实凭据写入报告或知识库。

## 修复原则

服务端必须重新执行认证和授权；输入校验应采用允许列表和规范化；敏感操作应有 CSRF 防护、幂等控制、审计和限流；错误响应不应暴露堆栈、密钥或内部拓扑。
